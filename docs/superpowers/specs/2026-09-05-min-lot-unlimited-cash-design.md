# unlimited_cash 下名义额凑不满最小成交单位时按最小成交单位买入

日期：2026-09-05　状态：已实施并实跑验证（见文末「验证」）；2026-09-07 补录科创板 100 股绕过修正，下文 `shares <= 0` 触发条件已被取代（见文末「补录」）

## 具体问题场景

信号集 `20260903_105046_selection_5bc6dd3c`（9 策略 / 14 天 / 全市场）里，
`600519` 贵州茅台在 2026-08-19 被 `bbi_short_long` 选中，买入日开盘价 1291.26 元。
回测配置是无限资金模式、每笔名义金额 50,000 元。

引擎按 `shares = int(budget / open_price / lot_size) * lot_size` 算股数：

```
int(50000 / 1291.26 / 100) * 100 = 0
```

`shares <= 0` 走原来的分支 → 记一条 `reason="资金预算不足"` 的 skip，**这笔交易不存在**。

14 天窗口里 5,555 只股票有信号，峰值开盘价 > 500 元（50,000 ÷ 开盘价 < 1 手）的有
15 只（0.27%），最贵的是 `688808` 2445 元。全市场那次回测因此丢掉 **78 笔买入尝试**，
涉及 10 只代码：`002371 300308 300757 600519 688072 688256 688498 688627 688795 688802`。

## 问题在哪

三个叠在一起：

1. **和资金模式自相矛盾**。`unlimited_cash` 的语义是"不校验现金、想投多少投多少"
   （`engine.py:297-298` 直接把 budget 设成 `fixed_cash_per_trade`，不看权益）。
   结果反而是钱"不够"——50,000 元在这里是**投多少的意思**，不是**能不能投的意思**，
   却被当成了硬约束。
2. **skip 文案是假话**。报告里挂着"资金预算不足"，而这一轮压根没有预算限制。用户看到
   这条会去找资金配置，实际上应该看到的是"这只票一手 13 万，比名义额贵"。
3. **整笔信号静默消失**。不是"少记一笔"，是这个策略选出的票在 trades 里根本不存在，
   胜率、盈亏、笔数都建立在一个被价格门槛筛过的子集上——恰好筛掉的是最贵的一批。

## 决定

名义额凑不满最小成交单位时，**按最小成交单位买满**，该笔实际投入可以超过名义金额：

- 主板 / 创业板：一手 100 股（茅台 1300 元 → 按 13 万算）
- 科创板（`688` / `689`）：最小成交单位 200 股，不是一手 100 股（`688498` 1631 元 → 按 32.6 万算）

`realistic`（真实现金）模式**不变**，仍然记"资金预算不足"skip——在那里现金是真的会不够，
那句话是真话，而且不允许花光账户现金去买一只票。

## 影响面

- `execution.py`：新增 `min_trading_shares(*, code="")` → 688/689 为 200，其余 100。
  与既有 `_limit_pct` 用同一套代码前缀认板块的约定
- `engine.py`：`shares <= 0 and mode == "unlimited_cash"` 时
  `shares = max(lot_size, min_trading_shares(code=code))`；`max()` 保证 `lot_size` 配得比
  200 大时不会被板块规则降级
- `__init__.py`：导出 `min_trading_shares`
- `presenters._effective_trade_rule`：参数快照新增 `position_limits`
  （`target_positions` / `max_positions` / `max_single_position_pct` /
  `max_daily_new_positions`），前端 `StrategySnapshots.tsx` 增一行
  "不限持仓数量、开仓节奏与单票占比（选出多少买多少）"或实际上限文案
- 前端资金模式文案补最小成交单位口径，不再只说"不做现金不足限制"
- **口径变化**：单笔实际投入上限从"≤ 名义金额"变成"≤ 名义金额向上取整到手，
  或最小成交单位（取大者）"。极端情况下单笔名义额 5 万可以花到 32 万

## 补录（2026-09-07）：科创板 100 股绕过最小成交单位

第六轮 review 发现原 `shares <= 0` 触发条件有个洞：**只挡住了"凑不满一手"，没挡住
"凑得满一手、但低于板块最小成交单位"**。

具体场景：科创板（`688` / `689`）最小成交单位是 200 股。一只 300 元的科创板票，
名义额 5 万 ⇒ `int(50000 / 300 / 100) * 100 = 100` 股。`100 > 0` ⇒ 原来的
`shares <= 0` 分支不触发 ⇒ 引擎照 100 股下单——**低于 200 股最小成交单位，是无效单**。
原口径"按最小成交单位买满"在科创板高价段（约 250–500 元）形同虚设：恰恰是这段价格
算得出 100 股、又够不到 200 股。茅台那类"凑不满一手"的反而被原修法接住了，漏的是中间这一段。

修法（`engine.py:310-333`）：

- 先算 `required_shares = max(lot_size, min_trading_shares(code=code))`
  （科创板 200、其余 100；`lot_size` 配得更大时取 `lot_size`）；
- 触发条件从 `shares <= 0` 改成 `shares < required_shares`；
- `unlimited_cash`：补齐到 `required_shares`（100 股 → 200 股）；
- `realistic`：仍记"资金预算不足"skip——补齐到 200 股的金额必然超预算，硬抬会破坏
  预算约束，与上文「决定」一致。

这取代了上文「具体问题场景」「影响面」里 `shares <= 0` / `shares = max(lot_size,
min_trading_shares(code=code))` 的写法：那行 `max()` 本意是对的，但只在 `shares <= 0`
时才执行，漏掉了 `0 < shares < required_shares` 这一段。

新增 3 条科创板测试（`tests/domain/test_backtest_engine.py::TestMinimumLotForHighPrice`）：
`test_star_market_rounds_up_when_budget_covers_only_one_lot`（300 元算出 100 股 → 补齐到
200）、`test_star_market_keeps_truncated_shares_when_above_minimum`（够 200 股以上则按手
截断、不再多买）、`test_realistic_star_market_skips_when_budget_below_minimum`（realistic
下不足 200 股仍 skip）。该类测试由 4 条增至 7 条，全套 533 passed（2026-09-07）。
